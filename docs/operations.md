# 運用手順

## 当日の操作

1. PC にログインすると GUI が自動で開きます（デーモンは常駐）。
2. カードを挿します。左右の「メディア 1 / 2」にそれぞれの進捗が出ます。
3. **緑の「✔ 取り外し可能」** が出たら抜いてかまいません。
   - **黄の「▲ 取り外し可能（失敗あり）」**: 一部のファイルが 3 回試しても読めませんでした。
     ［詳細を表示］で失敗ファイルを確認し、カードは保管してください。同じカードを挿し直すと
     同じセッションで失敗分を再試行します。
   - **赤の「✖ まだ取り外さないでください」**: アンマウントに失敗しました（ファイルを開いている
     アプリがある等）。そのアプリを閉じて［アンマウント再試行］を押してください。
4. NAS 転送は下のカードに表示されます。カードを抜いた後も続きます。

| 表示 | 意味・対応 |
|---|---|
| 容量確保待ち | SSD の空きが 20GB + 必要量に足りません。NAS 転送が終わって SSD が空けば自動で始まります |
| 処理中断／同じメディアを再接続 | コピー完了前に抜かれました。同じカードを挿すと続きから再開します |
| NAS 転送待機／SSD 保持中 | NAS に接続できません。SSD にデータを保持したまま自動で再試行しています |
| NAS が n 秒応答していません | NAS への読み書きが止まっています。2 分（設定 `transfer.stall_timeout_secs`）応答がなければ自動で切り離して後で再送します。「今すぐ再試行」ですぐにやり直せます |
| 応答のない NAS 処理 n 件を切り離しました | NAS・ネットワークを確認してください。SSD のコピーは保持され、NAS 復旧後に自動で再送します |
| 最終確認（NAS 上のファイルを読み直して照合）i/n 件 | 転送はすべて終わり、SSD を消す前に NAS 上の全ファイルを読み直しています。大きなセッションでは時間がかかります |
| 転送は完了。n セッションの完了処理を…／要対応 n セッション | 転送待ちが 0 件でも完了していない理由です。要対応は同じ SD を再接続すると続きから取り込みます |
| ▲ 保存先が未初期化 | 設定画面で［保存先を初期化］を押してください |

NAS 転送を再開せず、SSD に残ったストックを破棄する場合は、［履歴］で対象セッションを選び、
［SSD ストックを削除（確認）］を押します。NAS 未検証のデータも削除されるため元に戻せません。
メディア処理中のセッションは削除できません。削除に失敗した場合は、表示されたエラー
（ファイルを開いているアプリ、マウント境界など）を解消してから再実行してください。

## NAS 転送が止まったときのファイル別操作

1. メイン画面の NAS 転送欄から［ファイルごとの操作・履歴］を開き、対象のセッションを選びます。
2. ファイルにチェックを付けます。単一ファイル・複数ファイル・このページの対象全件を選べます。
3. ［選択分を再試行］で、選んだファイルだけ NAS 転送を再開します。全体が一時停止中の場合は［再開］も必要です。
4. 不要なファイルは［選択分の PC コピーと転送キューを削除…］から、対象・件数・容量を確認して確定します。
   PC 内のコピーと転送キューを削除し、元の SD と NAS 上の既存ファイルは変更しません。取り込み中は削除できません。
5. データを残して転送だけ止める場合は［選択分の転送を中止（PC に残す）］を使います。

NAS 側の試行回数・エラー・次回再試行時刻を表示し、一覧は3秒ごとに更新します。200件ずつページを切り替えられます。
PC コピーを削除すると NAS 再試行はできません。削除失敗は「削除待ち」として残り、削除を再実行できます。
削除途中で終了した場合は、次回起動時に記録済みの削除を続行します。中止した転送は一括再試行や再起動では再開しません。
削除・中止したファイルを含むセッションは、全件成功や残りの PC コピーの自動削除の対象にしません。
NAS の I/O が応答しない場合は、10秒の停止待ちで操作を打ち切り、未確定と表示します。通信回復後に再実行してください。

## コマンド

```bash
sd-backup status            # 状態
sd-backup doctor            # 依存・サービス・容量・NAS 設定の診断
sd-backup sessions          # セッション一覧
sd-backup files <SESSION>   # 問題のあるファイル（--all で全件）
sd-backup retry-nas         # NAS 転送を今すぐ再試行
sd-backup export-logs ~/Desktop
sd-backup restore --session <SESSION> --to ~/Restore     # 元のカード構成で復元
sd-backup restore --manifest /path/to/<folder>/manifest.json --nas-root /path/to/share --to ~/Restore
journalctl --user -u sd-backup-daemon -f                  # ログ
systemctl --user restart sd-backup-daemon                 # 再起動（処理中のコピーは安全に中断・再開）
```

## ファイルの場所

| パス | 内容 |
|---|---|
| `~/.config/sd-backup-manager/config.toml` | 設定（秘密値なし） |
| `~/.config/sd-backup-manager/formats.toml` | 分類用の拡張子定義（編集してデーモン再起動で反映） |
| `~/.local/share/sd-backup-manager/state.sqlite` | 状態 DB・永続カタログ |
| `~/.local/share/sd-backup-manager/logs/` | 日次ログ（30 日保持） |
| `~/SDBackupStaging/sessions/sd1/<YYYYMMDDHHMMSS>/` | SSD 一時保存。SD の元の構成と `manifest.json`（NAS 検証後、または履歴から明示的に破棄した場合に削除） |
| NAS `<共有>/sd1/<YYYYMMDDHHMMSS>/` | SD の元の構成と `manifest.json`。毎回全ファイルを保存 |

Windows は `~` を `%USERPROFILE%` に読み替えます。画面の［PC 内の保存先を開く］から開けます。
同一秒の日時には連番を追加します。複数パーティションは日時の下の `P01/`・`P02/` に分けます。
旧セッションは SSD の `sessions/<UUID>/`、NAS の `<YYYYMMDDHHMMSSNN>/` に維持します。
カード番号は DB に保持します。カード固有シリアルのない USB リーダーではフォーマット後に新番号になります。

## 本番前の推奨事項

- NAS 側でスナップショット、または別媒体へのバックアップを設定する（NAS が唯一の長期保存先になるため）。
- 本番と同じカード・カードリーダー・NAS で [acceptance.md](acceptance.md) の実機試験を行う。
- `sd-backup doctor` がすべて ✔ になることを確認する。
